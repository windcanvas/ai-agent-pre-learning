## 模型选型参考答案

模型选型的核心维度：**能力要求 × 成本预算 × 上下文长度 × 响应延迟 × 需要创造力还是确定性**

---

### a) 智能客服（预算有限，每天 10 万次对话）

**推荐模型：** 通义千问 qwen2.5-7B / Llama 3.1 8B **本地部署**，或调用 **gpt-4o-mini / 豆包 lite / 通义千问 turbo** 这类轻量级 API

**为什么：**

| 考量维度 | 分析 |
|---------|------|
| **能力要求** | 智能客服大多是 FAQ 级别（查订单、退换货政策），7B 级别小模型完全够用，不需要 GPT-4 级别的推理能力 |
| **成本** | 10 万次/天 ≈ 300 万次/月，用 gpt-4o 级别的模型成本会爆炸；小模型 API 或本地部署可以把成本压到原来的 1/10~1/50 |
| **延迟** | 用户等客服回复不能超过 2 秒，小模型推理更快 |
| **上下文窗口** | 单轮对话通常只有几轮，8K~32K 窗口足够 |
| **锦上添花** | 可以配合 **RAG（检索增强）** 把知识库塞给小模型，客服场景效果和大模型差距极小 |

---

### b) 审查 5000 行 Python 代码的安全漏洞

**推荐模型：** **GPT-4o / Claude 3.5 Sonnet / 通义千问 qwen2.5-72B**，优先选 **Claude**（长代码理解能力口碑最佳）

**为什么：**

| 考量维度 | 分析 |
|---------|------|
| **能力要求** | 代码审计属于**高难度推理任务**——要跨函数追踪数据流、识别 SQL 注入/XSS/反序列化等微妙模式，7B 小模型会大量漏报 |
| **上下文窗口** | 5000 行 Python ≈ 约 15 万~20 万 Token，需要 128K 以上窗口（Claude Sonnet 200K / GPT-4o 128K~2M）才能一次性吃下整个文件，不会"看了后面忘了前面" |
| **成本敏感性** | 代码审计是低频任务（一个项目审一次或每次 PR 审一次），单次成本高但总花费不大，值得用最强模型减少漏报 |
| **确定性** | 漏报比误报更危险，宁可模型保守一点多提示，也不能用弱模型漏掉真实漏洞 |

### c) 写一首关于 AI 的七言律诗

**推荐模型：** **Claude 3.5 Sonnet / GPT-4o / 通义千问 qwen-max / 豆包 4.0**，**Temperature 设 0.8~1.2**

**为什么：**

| 考量维度 | 分析 |
|---------|------|
| **能力要求** | 七言律诗有严格格式约束（8 句、每句 7 字、颔联颈联对仗、平水韵/新韵押韵），小模型经常凑不齐押韵或对仗乱，需要强模型掌握格律知识 |
| **创造力需求** | 这类创作任务需要"意料之外情理之中"，选中等偏上的 Temperature（0.8~1.2），否则写出来的全是套话 |
| **中文文化理解** | 国产模型（通义/豆报/DeepSeek）在古诗词语感上通常不输甚至略优于 GPT-4o，对典故的调用更自然 |
| **成本** | 单次推理几毛钱，无所谓成本，优先质量 |

> 💡 小技巧：给模型看几个七言律诗的范例（Few-Shot），效果会比空手写好非常多。

---

### d) 解一道 IMO 数学竞赛题

**推荐模型组合：** **DeepSeek-V3 / GPT-4o 搭配 o1 / Claude 3 Opus**  
**最佳实践：开 Chain-of-Thought + 多轮自检（Self-Consistency，采样多个答案取多数）**

**为什么：**

| 考量维度 | 分析 |
|---------|------|
| **能力要求天花板** | IMO 是人类数学竞赛的顶级难度，对**多步链式推理、抽象构造、反例验证**要求极高，普通模型基本做不对。必须选推理专项模型：GPT-4o 推理版 / o1 / DeepSeek-R1 / Claude Opus |
| **推理链长度** | IMO 解答通常需要几十步到上百步的推导，不能一步到位，必须用 Chain-of-Thought（让模型"先写思考过程再给答案"） |
| **Temperature 策略** | **推理时温度可以稍高**——多采几条推理路径（Self-Consistency 技巧），最后投票选出出现次数最多的答案，比单条路径正确率高一大截 |
| **工具增强（强烈推荐）** | 只靠纯 LLM 解 IMO 依然很难，配合 **SymPy（符号计算）/ Z3（约束求解器）/ Lean（定理证明器）** 这种"AI + 计算器"组合，正确率会明显提升 |
| **成本** | 低频任务，最贵的 o1 一次也才几块钱，完全值得 |

---

### 总结：一张表快速记忆

| 场景 | 模型级别 | 核心关键词 |
|------|---------|-----------|
| 智能客服量大 | 小模型 7B / 轻量 API | 低成本、低延迟、RAG |
| 代码安全审计 | 最强闭源（Claude / GPT-4o） | 长上下文、低漏报 |
| 格律诗词创作 | 中强闭源或国产大模型 | 中文文化、创造力 |
| IMO 竞赛数学 | 推理专项模型（o1 / DeepSeek-R1） | 多步推理、工具增强、自检 |
